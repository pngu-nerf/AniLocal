# AniLocal — Claude Code Working Rules

> Always-loaded project context. This file holds the durable rules that apply every session; keep it under ~150 lines. Where the details live: **`docs/ARCHITECTURE.md`** is the maintainer front door (layers, seams, "where is X"), **`docs/multi-source-plan.md`** is the source-plugability program and everything parked, and **`ROADMAP.md`** is stage history plus the distribution track. Read the one that matches the work.

## What this is
AniLocal is a **light, offline-first, distributable** desktop anime library player. It scans the user's anime folders, identifies files by parsing their names, enriches them from an ordered list of metadata sources (**AniList** by default — public, no account — with Kitsu and Jikan as fallbacks), caches everything locally, and plays via **libmpv (media_kit)**. Built to be downloaded by anyone — no server, no account, point at a folder and go. macOS first; Linux/Windows later by recompile.

## Current stage
**Post–Stage 6. Current schema: v18.** Stages 0–6 complete (offline cache · scan/identify · manual fix-match · multiple libraries · libmpv playback · local watch state). First post-Stage-6 features built: **multi-source episodes** (schema v7), **folder-priority drag-reorder** (no schema change — reuses Stage 5 `sortOrder`), **Up Next / auto-play next episode** (within-season; no schema change), **OP/ED auto-skip** (AniSkip, schema v8 — the reclaimed v8), **stable volume identity** (schema v9), **immediate library population** (schema v10), **missing episodes** (ghost tiles + hide/unhide, schema v11), **manual watched-override** (a sticky per-episode "mark watched/unwatched" that beats the auto-threshold, schema v12 — `watch_state.watched_manual`), **per-show preferences** (cover display **picture-mode** — normal / blur / removed — + hide-next-episode, schema v13 — `show_preferences`), **surrogate series identity** (schema v14 — `anilist_id` renamed to `series_id` across all 8 tables + a `series_external_ids` side table), **pluggable metadata providers** (schema v15 — `series_cache.id_mal` dropped, now one row in the side table), **pluggable skip sources** (schema v16 — `skip_segments.source`), **skip corroboration** (schema v17 — per-window confidence), and **skip re-resolution** (schema v18 — `skip_segments.resolved_key`). The UI was also rethemed to the **VFD "fine-instrument" look** (Technics SC-CH900; `lib/ui/theme/`) — no schema change. Remaining deferred features are built one at a time — do NOT pull more than one forward. **Per-show preferences (v13):** per-show user prefs keyed by show identity (`series_id`), in `show_preferences` (impl `DriftLibraryRepository` via `ShowPreferencesRepository`; UI reads `Series.pictureMode`/`nextEpisodeHidden`). Two prefs today: **picture-mode** — how the cover is DISPLAYED: `normal` / `blur` (NSFW/spoiler) / `removed` (black "?" placeholder) — and **hide-next-episode** (suppress the card's "Next episode" button for that show). Picture-mode is purely display: the cached cover image is NEVER altered or deleted, so switching is instant and fully offline. **Sacred (seam #5):** the fill path (`applySync`) and `refreshMetadata` have NO writer, so a refresh/rescan never wipes it. Modeled as a small value object (`ShowPreferences{pictureMode, nextEpisodeHidden}` in `lib/domain/models/`) so a new per-show pref is one field here + one column — not a parallel store. A global **Settings → "Hide Next Episode"** master switch overwrites every cached show's flag (`setAllNextEpisodeHidden` — a deliberate overwrite of per-show choices, not a merge). The v12→v13 migration just creates the new empty table, so existing populated caches are untouched.

**Surrogate series identity (v14):** the universal primary key is now `series_id`, an **opaque local surrogate** — not any provider's id. `anilist_id` was renamed across all **8** tables (`series_cache`, `file_cache`, `match_overrides`, `watch_state`, `source_overrides`, `skip_segments`, `hidden_episodes`, `show_preferences`); a show's provider ids live in the new **`series_external_ids`** (PK `{seriesId, provider}`, **UNIQUE `(provider, external_id)`** — that constraint is load-bearing, it turns a silent identity fork into a loud failure). Needed because sources are becoming user-reorderable and **4,655 Kitsu shows have no AniList id**, so no provider's id can be the key. **Identity was PRESERVED** (`series_id` := the old `anilist_id`), so nothing was re-keyed and cover-art files — named by id on disk — still resolve; **no file was touched**. The rename is `ALTER TABLE … RENAME COLUMN`: schema-text-only, **zero rows touched**, so the only outcomes are "all applied" or "rolled back byte-identical". **The subtle rule** (`_migrateToSurrogateIdentityV14`): only rename a table that existed BEFORE this upgrade started — `m.createTable` emits the CURRENT shape, so a table created by an earlier step of the same run is already `series_id` and renaming it fails with "no such column". Each rename is therefore paired with the version that creates that table; a single-hop test never catches this, so `migration_v14_test.dart` includes a **v8 → v14 leapfrog**. The three id bands (placeholder / provider-seeded / minted) live in ONE file, `lib/data/cache/series_identity.dart`. `Series.anilistId` is now **separate from and nullable alongside** `Series.seriesId` — anything rendering "AniList #…" reads it and omits the label when null rather than printing the surrogate. (`series_cache.id_mal` briefly duplicated the `mal` row; v15 dropped it and repointed the AniSkip lookup at the side table, so the MAL id has exactly one home.)

**Pluggable metadata providers (v15):** "what is this show" now comes from an ORDERED list of `MetadataProvider`s (`lib/data/metadata/`), not from AniList directly. Contract is two reads — `searchCandidates` / `fetchByProviderIds` — both returning domain models; every failure is a `MetadataException` carrying `MetadataFailure`, so the chain falls through and the UI still says whose end the fault is on. `SeriesMatcher` and `FixMatchService` share ONE list from the composition root, so scan and fix-match can never disagree about priority. **A provider that answers with no candidates has ANSWERED** — that is a no-match and stops the chain; only a failure falls through. An **unconfigured** provider (awaiting a client ID) is skipped, not counted as down; if nothing could be tried at all that is a FAILURE, never a no-match, so files stay pending rather than becoming confirmed-unmatched. **`CacheDatabase.ensureSeriesId` is the SOLE minting site** and the identity rule lives there: match on **ANY** id the answer carries (not just the answering provider's — MAL is the practical bridge, since AniList and Kitsu both publish it), otherwise take the AniList id as the series id (that IS the provider-seeded band), otherwise mint. When several existing series match, the **lowest wins and nothing is merged**, and an id already owned by another series is **never re-pointed** — merging on the fill path could clobber a fix-match unrecoverably (seam #5). `Series` carries `ExternalIds{anilist, mal, kitsu, anidb}` instead of separate id fields; `series_cache.id_mal` is gone (v15) and the AniSkip lookup reads the side table, so the MAL id has exactly one home. Fix-match now records ids too — previously a fix-matched show got no MAL id and therefore no AniSkip until some later refresh happened to backfill it.

**MyAnimeList provider (C5) — BUILT, TESTED, DELIBERATELY NOT SHIPPED.** `kShipMyAnimeListSource` in `main.dart` is **false**; flipping it is the whole re-enable, and everything behind it keeps running in the suite so it can't rot. Off because MAL is the only source needing a credential (no keyless mode — unauthenticated reads are 403), the benefit is small (AniList + Kitsu already identify; the MAL id AniSkip wants already comes from AniList and the cross-map), and the cost is a real onboarding wall plus **no batch-by-id endpoint** (~1 req/s, one per id). AniLocal can never ship a shared key: MAL's agreement §2(a)/§3(c) forbid sharing or exposing a client ID, which a string in a downloadable binary cannot satisfy. **`docs/myanimelist-registration.md` holds the full registration flow, the form field-by-field, the live-probed error shapes, and the guide-button design** — so the decision can be revisited without re-deriving any of it. Still live while parked (and needed by Anime Skip in D3): per-source client-ID storage, `requiresClientId`/`setupUrl`/`setupInstructions`, `MetadataFailure.unauthorized`, and the key dialog — the last of which is **currently unreachable in the UI**, since no shipped source needs a key.

**Jikan provider (C4):** `lib/data/jikan/` — MyAnimeList's data through the community proxy, **keyless**. **FALLBACK-ONLY and never the source of truth**: the data is the richest of the four but the transport is one volunteer service with no SLA, measured at ~30% (0/12, 0/5, 1/3, then fully 504 while MAL itself stayed up). Enforced structurally, not by convention — `MetadataProvider.isFallbackOnly` + `applySourceOrder`'s stable partition means such a source can never outrank one that isn't, however the user drags it; the settings row says "Fallback only — never the source of truth" and visibly settles back rather than pretending the drag took. If EVERY source is fallback-only the rule does nothing (something has to answer). Two Jikan-specific problems handled: (1) it publishes **only MAL ids**, so `JikanMetadataProvider` enriches each answer from the cross-map (MAL → AniList) — otherwise a Jikan-identified show would mint a fresh identity for a series AniList already names; (2) it documents **3 req/sec** and has **no batch-by-id endpoint**, so the client spaces requests (injectable `minInterval`, so tests don't sleep) and `fetchByProviderIds` is one request per id — tolerable only because this source runs after the others have failed. Same charset trap as Kitsu (`application/json`, no charset → latin1) so it decodes bytes as UTF-8. **Live-validated, partially.** `test_live/` holds real-API tests. They sit OUTSIDE `test/`, which is the only mechanism that actually works here — `flutter test` walks `test/` only, and the tag-preset flag that would re-include tagged tests is `dart test -P`, which `flutter test` does not accept. Run them with `flutter test test_live/` — a suite whose result depends on someone else's uptime stops meaning anything, but mocked fixtures can only prove we parse what we THINK is returned. Result: `/v4/anime/{id}` **passed twice against the live API** (Japanese title intact — so no latin1 regression — plus episode count, format normalisation and image URL). `/v4/anime?q=` was **never reached**: ~15 minutes of continuous retrying returned nothing but 504. Its mapping therefore rests on fixtures alone; re-run the harness when Jikan next recovers.

**Why Jikan will probably stay unreliable:** its own 504 body says *"Jikan failed to connect to MyAnimeList. MyAnimeList may be down/unavailable or refuses to connect"* — while myanimelist.net answers a browser with 200. So MAL is refusing JIKAN, not failing generally. That is between those two parties and outside this app's control, so it is unlikely to improve, and it is the strongest argument for the official-API route (C5, user's own client ID) being the real way to get MAL data. The verbatim error body is pinned in a test.

**Kitsu provider (C3):** `lib/data/kitsu/` — a second metadata source, **keyless** (no account, no key, no registration) and the only rich one still answering while AniList's API is disabled. **Every request asks `include=mappings`**: Kitsu is slow (1.5–10s measured), so resolving each candidate's AniList/MAL ids with a second request would be unusable — the mappings ride along in `included`, linked via `relationships.mappings.data`. That is what lets a Kitsu answer carry the AniList id, so a show identified during an outage resolves to the SEEDED identity and needs no repair when AniList returns. **Two traps closed here:** (1) Kitsu returns **raw UTF-8 with no `charset`**, and Dart's `http` falls back to **latin1** in that case — `response.body` mojibakes every Japanese title, so both clients now decode `response.bodyBytes` as UTF-8 (JSON is UTF-8 per RFC 8259; AniList only escaped its way out of this by luck). (2) `Series.format` renders raw in the UI, so Kitsu's `movie`/`special` vocabulary is normalised to the shared tokens at the provider boundary (`normalizeSeriesFormat`, `lib/domain/models/series_format.dart`) — canonical values are AniList's, because every cached row already uses them. `classifyHttpFailure` (`lib/data/http_failure.dart`) is now shared by both clients so they attribute failures identically. `ArtCache.ensureCover` takes the previously-stored URL/path and **re-downloads when the source URL changed**, deleting the superseded file — without it a source switch would update every field except the picture.

**Minimum skip length (Settings → Skip → "Ignore skips shorter than", seconds, default 0 = off):** sources occasionally mark a few-second sting or scene divider that a chapter parser reads as a theme, and offering that as "skip the intro" is noise at best. Applied on the **READ path** (`dropIfShorterThan`, used in `DriftLibraryRepository._toEpisode` — the ONE place every Episode is built, so player, timeline markers and detail agree) rather than at write time, so changing the floor takes effect at once instead of needing a rescan. The floor is wired onto the repository AFTER construction because `DriftSettingsRepository` is built FROM it (show-preferences delegate), so neither can be the other's constructor argument. Clamped 0–600s on both read and write, and the field commits on blur/submit rather than per keystroke — mid-typing "3" on the way to "30" is a different setting.

**Sync summary names its sources:** the scan snackbar said "N AniList lookups" whoever answered, so a scan that fell through to Kitsu because AniList was down looked identical to one AniList served. `SyncSummary.lookupsBySource` (token → count) replaces `anilistLookups`; `MatchResult.source` carries which provider answered, stamped in `SeriesMatcher` (ranking compares titles and has no idea who supplied the candidates). The UI resolves display names from the SAME descriptor list the settings page shows, so the two can never call one source different things, and falls back to the raw token rather than inventing a name.

**Skip corroboration (D5, v17):** cross-check skip sources against each other, off by default (⚙ Settings → Skip → "Cross-check sources"). On, every enabled source is asked instead of stopping at the first with data, and their answers are reconciled: two placing the theme in the same span → `corroborated`; both answering but putting it in materially DIFFERENT places → `conflicting`; one answering → `single`. **Agreement is judged by OVERLAP, not by matching edges** (`kSkipCorroborationMinOverlap` = 0.60, intersection over union so a mismatched LENGTH counts against it too). That replaced a ±2s test on each edge, and the replacement is measured: of the 59 disagreeing pairs on the reference library, **nothing fell between 45% and 69% overlap** — 50 sat at 70–97% and were the same theme with a legitimately different boundary (a uniform ~5s offset from AniSkip targeting another release; a ~11s offset where the chapter bundles a streaming ident in with the opening, which a viewer WANTS skipped; an outro whose start matched within a second but ran ~4s longer), while 9 sat at 0–44% and were every case of the leading source having picked the wrong chapter — `inferSkipsFromChapters` taking a cold open of theme-like length, with the real opening starting exactly where that window ended. The edge rule condemned both groups alike, treating a 5s boundary difference as severely as a 60s difference in location. Since the top source supplies the times and is now the locally-authored one, what the gate must catch is the top source picking the wrong chapter — which is low overlap, every time. **A source with NO window is NOT a disagreement** — it is simply excluded from judging that window. This is the rule the feature turns on: partial coverage is the norm for skip data, so counting silence as dissent would mark nearly everything conflicting and disable auto-skip library-wide. **Verdicts are PER WINDOW** (`intro_confidence`/`outro_confidence`, replacing v16's single placeholder): a mixed library routinely has a corroborated intro beside a lone outro, and one verdict for both would either forfeit the intro's corroboration or overstate the outro's. **The top source always supplies the times** — corroboration decides only how far to trust them, so reordering still determines what you get. Agreement with ANY other source suffices, so one outlier can't veto two that agree. **Auto-skip is gated on it** (`video_zone.dart`): a `conflicting` window is still offered as a button but never fires on its own — skipping into real content is what a viewer cannot undo, an unoffered skip is a keypress. The v16→v17 migration DROPS the orphaned `confidence`; its guard must be `from >= 8`, matching v16's add, because a v15 cache has the column added on the way through — guarding on `from >= 16` left the orphan on exactly the path a real cache takes.

**Pluggable sources — the program is COMPLETE; three sources are PARKED.** Prompted by AniList disabling its public API (403 "temporarily disabled"), which proved a single provider is a single point of failure. Shipped: two separate ordered, individually-switchable source lists — **metadata** (AniList SoT · Kitsu · Jikan fallback-only) and **skip** (embedded chapters SoT · AniSkip) — sharing ONE reorder mechanism with library folders, over a surrogate identity (v14) that no provider owns. **Parked with their framework deliberately kept, and not expected to ship: MyAnimeList, Anime Skip, and fingerprinting** — all three are either account-gated or blocked on an unsettled dependency, and the retained code (the reserved skip tokens, `SkipLookup.siblingPaths`, and the whole client-ID subsystem including the key dialog) is UNREACHABLE at runtime **on purpose**. Do not garbage-collect it for having no callers; every such declaration says so at the site. **`docs/multi-source-plan.md` is the record** — the slice ledger, the measured research, the deviations, and the un-park path for each parked source.

**Skip re-resolution (v18):** a refresh re-asks an episode that already has a skip row when — and only when — the inputs that produced it have changed. Before this the refresh skipped any identity with a row at all, so **the first writer won forever**: reordering skip sources, switching one off, or turning on cross-checking could not reach an episode already in the library, which made corroboration inert on a real library (the reference cache had 157 rows, every `intro_confidence` 0). The decidable fact is stored: `skip_segments.resolved_key` records the enabled sources IN ORDER plus whether cross-checking was on (`skipResolutionKey`, `lib/domain/skip_corroboration.dart`), and the refresh re-resolves exactly the rows whose key no longer matches. Keyed on that rather than on a rank comparison because "one source answered and there was nothing to compare it against" and "cross-checking never ran here" are otherwise the SAME row — a rank rule would either re-ask everything every refresh or never re-ask at all. **Unchanged settings cost zero requests**, which is what keeps refresh incremental. `''` is the v18 default and MEANS "unknown inputs", so every pre-v18 row re-resolves once and then settles; it is deliberately not backfilled to the current key, which would freeze those rows as they are. When NO source has data any more the existing row is **left intact and its key left unstamped**, so a source that is merely down is asked again next refresh — the same retry an episode with no row has always had. ONE place decides what to ask (`_skipPlan`), so the scan and the refresh cannot stamp different keys for the same settings and see each other's rows as stale. **The RULE is an input to the key too** (`_ruleGeneration`): a verdict computed under an older notion of agreement is exactly as stale as one computed from a different set of sources, so changing `reconcileWindow`'s agreement test means bumping that generation — otherwise the change never reaches a library that has already been scanned.

**Chapters skip source (D2) — and the DEFAULT skip source since the corroboration pass:** ✅ the first real coverage win — **45% → 54%** on the reference library (127 → 154 episodes; 27 gain data they never had). Entirely LOCAL: no network, no MAL id, no outage to survive, and exact where present (chapters are authored against that encode; measured agreement with AniSkip ~0.5s). Containers are **parsed by hand** in `lib/data/chapters/` — `ffprobe` cannot ship and driving libmpv per file during a scan is too heavy. MKV: EBML walk of the Segment's top-level children, stopping at the first Cluster, reading `Chapters` + `Info` (`TimecodeScale` × `Duration`); `ChapterTimeStart` is **nanoseconds and unscaled**. MP4: `moov/udta/chpl` (Nero), version-1 layout is `4 ver+flags, 4 reserved, 1 count`, then per chapter an **8-byte start in 100ns units** and a length-prefixed title; duration from `mvhd`. Both **seek past the media payload** using declared sizes, so a 650MB file costs a handful of reads. **Every failure returns empty, never throws** — this runs over whatever is on disk. **Containers store STARTS only**: a chapter ends at the next start, and the LAST at the file duration, which is why duration is parsed at all. OP/ED is **inferred by LENGTH, never position** (`inferSkipsFromChapters`, `lib/domain/chapter_skips.dart`, band **85–100s** — measured mode exactly 90s): position genuinely varies, since ep 1 may open cold with the OP at 498s while eps 2–3 start it at 0. Position only tells the two apart — earliest qualifying span before the midpoint is the opening, latest after it the ending. **Declines rather than guesses**: chapters that merely divide scenes yield nothing, because a plausible-looking wrong window skips 90 seconds of actual episode. **Chapters OUTRANK AniSkip in the built-in order, and that is measured rather than assumed.** A chapter mark was authored against the exact encode on disk; AniSkip is crowd-sourced timings submitted against whatever release the submitter had, so where they differ the local one is right by construction. Cross-checking on the reference library flagged Cyberpunk: Edgerunners on all 9 episodes and **AniSkip was the wrong one** — 76.2s for an opening that starts at 71s, and since its window is exactly 90s the 5.2s late start pushes the END past the opening and INTO the episode, the one skip error a viewer cannot undo. `Sakamoto desu ga?` disagreed identically; six more shows disagreed on 13–36%. Costs nothing in coverage (only ~37% of files carry chapters and a source with no data falls through silently, so AniSkip still answers the rest) — the order only decides who wins where BOTH answer. Residual risk runs the other way: a chapters window is INFERRED from a duration band, so a ~90s non-theme span could in principle win where AniSkip's answer is curated; `inferSkipsFromChapters` declines rather than guesses, and corroboration is the backstop, since a bogus window disagrees with AniSkip and then never auto-skips. Validated by `test_live/chapter_reader_live_test.dart` against **all 285 real files: every one of the 105 with chapters matches ffprobe** (marks, counts, timings, duration), and 101 produce windows.

**Skip-source seam (D1):** "where is the OP/ED" is now its own provider family (`lib/data/skip/`), parallel to the metadata one and **deliberately separate** — the two answer different questions, fail independently, and are ordered independently, so they get two settings categories (**Metadata** and **Skip**) with two saved orders. AniSkip is now one entry in that list rather than the hardcoded path. **ONE `SourceListPanel` and ONE `SourceDescriptor` serve both families** (the descriptor was `MetadataSource`; a row is the same thing in both lists, so a near-identical copy would only drift), and both orders share one encoder in `DriftSettingsRepository`. `SkipLookup` is a single request shape carrying everything ANY source might key off — MAL id, file path, sibling paths, episode length — because chapters and fingerprinting key off the FILE while AniSkip keys off the MAL id, and threading three signatures through the fill path would be worse. **"No data" ≠ "failed"**: partial coverage is the norm here, so a source with nothing for an episode falls through silently to the next and only a genuine `SkipException` counts as failure; the first source WITH data wins and `skip_segments.source` records which. **The built-in order is chapters, THEN AniSkip** — see the D2 paragraph for why, and note it is load-bearing rather than incidental. v16's placeholder `confidence` column was replaced in v17 by a verdict per window, which is what gates auto-skip. AniSkip's exception finally carries a `MetadataFailure` (it predated the taxonomy) via the shared `classifyHttpFailure`. v16 is additive and defaulted, and leaves `source` **empty rather than backfilling 'aniskip'** so "we don't know where this came from" stays distinguishable from "we recorded that it did".

**Metadata settings tab (C2):** ⚙ Settings → **Metadata** — a drag-reorderable, individually-switchable list of metadata sources. Top is the source of truth; the rest are tried only when it fails. **Deliberately a SEPARATE category from Sources** — that one is library folders ("what do I own"), this one is metadata sources ("what is this show"); they fail independently, and `sourcesCategoryId` was already taken. **ONE reorder widget** (`lib/ui/widgets/xp_reorderable_list.dart`) now serves both, extracted from `SourcesPanel` rather than copied — there is exactly one `ReorderableListView` in the codebase, and the skip list is its third user. The ordering rule is a pure function shared by scan, fix-match and the panel (`applySourceOrder` in `lib/domain/models/source_preference.dart`): saved order wins; a **source not in the saved order is enabled by default and appended** (so shipping a new source is never silently off in existing installs); a preference naming a source this build no longer ships is ignored. Order persists in `app_settings` as a `token:1,token:0` list — no schema change, mirroring `skip_mode`. **Read fresh on every match, not snapshotted**, so reordering takes effect without a restart. An **unconfigured** source (awaiting a client ID) is still LISTED — hiding it would leave no way to discover it — but its checkbox is disabled and the chain skips it. The UI sees `MetadataSource` descriptors, never a `MetadataProvider` (seam #1); the composition root derives them from the ONE provider list.

**Manual watched-override (v12):** a **sticky per-episode "mark watched / unwatched"** toggle that BEATS the auto-threshold. `watch_state.watched_manual` (additive column, default 0). `setWatchedManual` wins over the auto path (`setWatched` becomes a no-op on a manually-set episode) and survives re-entry AND metadata refresh/rescan; it does NOT change the saved resume position. Keyed by episode identity `(seriesId, anchored position)` like the rest of watch-state — the single write path stays in the player (`video_zone.dart`), no parallel writer. The v11→v12 migration is additive defaulting 0, so existing rows keep their threshold-derived `watched` meaning (nothing is retroactively "manual").

**Missing episodes (v11):** the show page surfaces gaps in a series as **ghost tiles**, and lets the user **hide** ones they don't want. Per-episode truth lives in a pure domain function (`computeEpisodeSlots` in `lib/domain/missing_episodes.dart` → a list of `EpisodeSlot{number, status ∈ present/missing/hidden}`, NOT pre-grouped — a future heatmap consumes the same raw data); display grouping (`groupIntoRows`) and the "⬇N of M" tally (`computeDownloadTally`) are separate pure functions recomputed live, never stored. Detection: absent positions over **1..M** (AniList count) are missing; when **M is unknown**, ONLY interior gaps (between the lowest and highest OWNED standard episode) — never invent past the highest owned. Robust to messy numbering: only standard positions (≥1) are gap-detected, **specials (≤0) and out-of-range (>M, the existing "+X") are never flagged missing**. Display: a consecutive run of 2+ missing collapses to ONE **bundle tile** (first↕last joined by a line); isolated singles render individually; grouping is live so hiding mid-run re-splits automatically. **Hidden state is SACRED** (seam #5): `hidden_episodes` keyed by episode identity `(seriesId, episode)` like watch_state — the fill path (`applySync`) and `refreshMetadata` have NO writer, so a rescan/refresh never wipes it (covered by a test); hiding is always per-episode even from a bundle's "Hide all". Hidden episodes drop out of the list AND the completeness denominator ("11 of 12" → "11 of 11"), consistently on the card and show page. Interactions use ONE reusable checkbox multi-select (`lib/ui/widgets/multi_select_list.dart` — click-toggle, shift-click range from the last anchor, select-all↔deselect-all; built small + dependency-free) shared by the bundle hide-expand and the **Hidden tab** (appears only when ≥1 hidden; per-episode rows + Unhide; disappears when the last is unhidden — a TEMPORARY second tab in the episode area, final spot TBD post-GUI-revamp). Verbiage is hide/hidden/unhide throughout; **no confirm dialogs** (select-then-act is the safeguard). A global **Settings → Metadata toggle** ("Show missing episodes", default on) turns the whole feature off (no ghosts / no Hidden tab / counts ignore hidden). The v10→v11 migration just creates the new empty table, so existing populated caches are untouched.

**Immediate library population (v10):** the library reflects what's on disk the moment it's scanned — AniList is enrichment, not a gate for existence. There are now **THREE** file states, not two: **matched** (`file_cache.seriesId` set), **pending** (`seriesId` null + `pendingIdentification` true), and **confirmed-unmatched** (`seriesId` null + `pendingIdentification` false). PENDING = discovered on disk + parsed but not yet identified (offline, not-yet-tried, or a transient lookup failure) — shown in the grid as a **named placeholder** (parsed title, blank art) and **retried on every scan** until it resolves; CONFIRMED-UNMATCHED = AniList was consulted and genuinely found nothing (or no parseable title) — goes to the fix-match "unmatched" screen, never retried automatically. The scan is **two-phase**: phase 1 writes newly-seen titled files as pending rows with NO network and fires `LibrarySync.sync`'s `onDiscovered` callback (the UI reloads → placeholders paint instantly, even fully offline); phase 2 identifies and **upgrades the same record in place** (a match clears the pending flag and fills title+art; a no-match flips it to confirmed-unmatched; a lookup error LEAVES it pending). A failed/absent AniList never drops a file — at worst it stays a named placeholder. Placeholder grouping + the synthetic NEGATIVE series id (`placeholderSeriesId` in `lib/data/cache/series_identity.dart`, derived from the normalized parsed title; negative, so it can't collide with either positive band) live entirely in the **data layer** (`DriftLibraryRepository`); the UI consumes `Series.pending`. The synthetic id is an **ephemeral display/grouping handle — never durably stored**: the one path that could persist it is `watch_state` (you watched a placeholder before it identified), and `applySync`'s `promotions` **rekey those rows from the synthetic id to the real series id** the instant the file identifies, so resume progress carries over to the real series and no synthetic id survives identification (covered by a test). Source pins refuse a pending episode outright (`selectSource`/`clearSource` no-op on a negative id; the detail UI hides the picker), so the synthetic id never reaches `source_overrides` — seam #5 keeps its no-fill-path-writer guarantee. Match overrides are fingerprint-keyed and store the real target id. An override (fix-match) always makes a file matched, never pending. The v9→v10 migration is an additive column defaulting false, so every existing unmatched row keeps its confirmed-unmatched meaning and matched rows are untouched.

**Stable volume identity (v9):** `file_cache` is keyed by `(folder_path, relative_path)` — the owning folder's stable identity + the file's path within it — NOT an absolute mount path. `library_folders` is bound to a **volume UUID** (`volume_id` + `volume_subpath`) so a removable/NAS volume that remounts under a different `/Volumes` name (collision → `… 1`, rename, SMB-vs-USB) is **re-found by UUID and doesn't churn** the cache (no re-identify, no AniList refetch). All path↔identity resolution lives in the data layer behind `VolumeResolver` (`lib/data/folders/volume_resolver.dart`; macOS `diskutil` via `dart:io` `Process` — NO new pub dep): fast path = stored path still exists (no `diskutil`); else follow the UUID to the current mount; unmounted → "missing" (the existing reconnect path). Internal-disk folders stay **unbound** (`volume_id` null; their absolute path is already stable) and must never regress. Volume UUIDs **backfill on scan** (needs a mounted volume), so the v8→v9 migration only rebases paths by string (identity preserved → first post-migration rescan sees everything unchanged). Fix-match is **fingerprint-based** (stats the present file for `(size, mtime)`) — no path scheme, unaffected by remounts.

## Architecture — the seams (YOU MUST keep these)
1. **YOU MUST NOT import AniList, Drift, or scanner types inside `lib/ui`.** UI talks to repository interfaces and domain models only.
2. **The cache is the primary read path.** UI reads from cache; the pipeline fills it from the metadata sources at scan/refresh time. The UI MUST never wait on the network. Online vs offline is invisible to the UI.
3. **Every metadata source lives behind `MetadataProvider`** (`lib/data/metadata`), and each source's HTTP/JSON stays in its OWN module (`lib/data/anilist`, `lib/data/kitsu`, `lib/data/jikan`, …). A schema/API change touches exactly one module; adding a source is a new module + one list entry at the composition root. The fill path catches `MetadataException`, never a provider's own type.
4. **Identification lives behind one interface** in `lib/data/scanner`. The parser is swappable without touching anything else.
5. **YOU MUST NOT let a rescan overwrite a manual override** — match (which AniList entry/episode a file is) OR source (which copy a multi-source episode plays). Both override stores have NO write path from the fill path (`applySync`). User corrections are sacred.

Folders: `lib/ui`, `lib/domain` (models + repository *interfaces*), `lib/sync` (pipeline), `lib/playback`, and under `lib/data/`: `cache`, `scanner`, `folders`, `crossmap`, `metadata` (the seam) + one module per source — `anilist`, `kitsu`, `jikan`, `mal` — and `skip` (the seam) + `aniskip`, `chapters`.

## Pipeline & cache rules
- Read path: UI -> repository -> cache. Always.
- Fill path (scan/refresh only): scanner -> identifier -> metadata source (first that answers) -> write cache. Never on the read path.
- **Incremental only:** rescans process new / moved / removed files. NEVER refetch unchanged items.
- The cache is a **projection** — only fields the UI renders, keyed by `series_id` (AniLocal's own surrogate; see `series_identity.dart`). New field = deliberate Drift migration, not a reflex.

## Single-source-of-truth rules (prevent duplication debt) — see `docs/tech-debt-audit.md`
The test for every change: *"to change X, how many places must I edit?"* — the answer must be **one**.
- **Reuse before you build.** Before creating a UI element/widget, search for an existing one; if it exists, make it **configurable per location** (flags/slots) and reuse it — NEVER build a second parallel version. Two impls of the same thing WILL drift.
- **One source of truth for any value or rule used in 2+ places.** A display value, fallback, or format that appears more than once becomes ONE getter/util (e.g. `Series.displayTitle`, `Episode.displayTitle`, a shared `formatDuration`). Don't inline it again.
- **Cross-cutting config is injected as ONE object, not threaded.** App-wide values (settings) come from a single injected service/repository at the composition root — never a fan of individual `load*/set*` functions passed screen-to-screen, and never the same actions bundle constructed in two screens.
- **Never key list rendering or identity by positional index.** A row carries its own item; actions resolve from the row, not `list[index]`. Map selections by identity/value, not by an index into a list that could be filtered/reordered. (This caused a shipped bug.)
- **Prefer live reads over snapshots** for anything that can change while a screen is open. A deliberate snapshot MUST carry a comment saying why it can't go stale.
- **A heuristic that assumes runtime behavior states its assumption at the call site** (stream cadence, event ordering, timing — e.g. "a jump > 2s is a seek"), so an unrelated change can't silently break it.
- **Never clear known content to show a loading state.** Show loading only when there is genuinely nothing to show yet (first load). A refresh updates in place — re-assigning a `FutureBuilder`'s future, or nulling the field a screen renders from, tears the UI down to a spinner and back, which reads as a flash and silently drops scroll position and focus.
- **Delete code a migration orphans** in the same change — no leftover stubs/dead helpers.
- **Fail toward user-in-control.** When UI state is missing, stale, or uncertain, degrade by element ROLE, not uniformly: **navigation** fails AVAILABLE (never strand — derive from ground truth like `Navigator.canPop()` rather than cached state); **information** fails NEUTRAL (a placeholder/spinner, never last-known-specific — a stale specific value actively misleads, e.g. a title claiming you're on another page); **actions** fail ABSENT (a stale action still fires its side effect — wrongly hidden is merely inconvenient, wrongly shown is a trap). Never leave the user stranded, misled, or trapped.
- **Do NOT refactor the documented fragile player machinery** (`docs/player-regression-checklist.md`; audit §F: the tooltip-dismiss guard — BOTH the route observer and the resize hook, `Listener`-not-`MouseRegion` cursor wiring, focus ownership, layout clamps; fullscreen-as-state must not go back to being a route) without first reproducing the bug it fixes.

**OP/ED auto-skip** — ✅ BUILT (schema v8 — `series_cache.idMal` + `skip_segments`). **Offline-first, non-negotiable:** AniSkip OP/ED timestamps are fetched online at scan time (keyed by MAL id — since v15 from `series_external_ids` and the cross-map, not AniList's `idMal`, per anchored episode), cached in `skip_segments` (keyed by episode identity, like watch-state); **playback reads skips ONLY from the cache — the player makes no network call.** No cached data → no skip affordance (AniSkip coverage is partial; normal). Advancing is fully decoupled: only the end-of-episode up-next countdown advances (countdown = `min(5s, time remaining)`; true completion always advances). Skip trigger is state-based (`SkipRange.contains(pos)`) with a once-per-episode auto guard (manual seek back into a skipped window doesn't re-yank). (The MKV-chapter fallback this once listed as unbuilt is now D2, above.)
**Cross-database id map (A1)** — ✅ BUILT, no schema change. `lib/data/crossmap/` fetches Fribb/anime-lists `anime-list-mini.json` (weekly automated, ~5.8MB), reduces it to the two id pairs we read (AniList → MAL, AniList → Kitsu) and caches THAT derived file (`crossmap.json`, 7-day freshness) next to the DB. Fixes a real dependency: `idMal` — the key AniSkip needs — used to come ONLY from AniList's response, so a show identified while AniList was unreachable lost auto-skip permanently. `LibrarySync._resolveMalIds` now fills the gaps from the map, and `refreshMetadata` seeds its lookup from the CACHE as well as the live fetch (so an offline refresh still backfills skips for shows whose MAL id was already stored). **The provider stays authoritative — the map only fills nulls.** `CrossMapStore.load()` NEVER throws: fresh cache → stale cache → empty, and an empty map means every lookup returns null, i.e. exactly the pre-existing behaviour. No new pub dependency (reuses `http`).
**Refresh-metadata backfill** (`LibrarySync.refreshMetadata()`, ⚙ Settings → "Refresh metadata"): re-asks each metadata source BY ITS OWN ids (which is why the side table exists — our `series_id` means nothing to Kitsu or MAL) for already-cached series + fills missing skips, via no-prune upserts — so it backfills new fields (idMal, skips) onto an existing library WITHOUT a wipe and WITHOUT touching fix-matches / watch-state. Reusable for any later metadata field (the relation/watch-order extension will use it to backfill `series_relations`).
**Timeline markers** ✅ BUILT: the player shades the cached intro/outro spans on a thin skip-region strip over the seek area (`_SkipMarkersBar`, reads `Episode.introSkip/outroSkip`; span fractions clamped to `[0,1]` so an overhang never draws past the bar; missing window → nothing). UI-only.

**"Up Next" / next-episode + auto-play** — ✅ BUILT, **within-season only, NO schema change** (uses the existing episode list + watch-state). One resolver is the single source of "what's next": `WatchOrderRepository.nextEpisode(episode) → NextResult` in `data/` — next anchored episode in the same series, else `NoNextEpisode`. ALL callers route through it (player auto-advance, per-series "Next: Ep N" on cards + detail) — none computes "next" itself. Advancing is one entry point, `PlaybackController.advanceToNext()` (callable by any trigger). The auto-play overlay is a **pre-roll** countdown (appears in the last ~5s, advances instantly at end; cancelable; gated by a persisted on/off setting).
**`nextEpisode` returns `NoNextEpisode` at a season boundary today; cross-season via the AniList SEQUEL relation is the PLANNED EXTENSION at exactly that point — a deliberate seam, not unfinished work.** The extension lands there (the resolver's boundary branch) + a `series_relations` table when built; do NOT pull it forward.

**Multi-source episodes** — ✅ BUILT (schema v7). One logical episode = files sharing `(AniList entry, anchored position)`; the repository collapses them to one `Episode` carrying its priority-ordered `sources`. Library folders are an **ordered priority list** (`library_folders.sortOrder`, top = preferred); the default source is the highest-priority folder that has the episode, falling back down. A per-episode manual source override (`source_overrides`, keyed by episode identity) beats the default and is **sacred across rescans** (seam #5, source dimension — no fill-path writer). Folder priority is user-controlled by **drag-reorder** in the folders screen (reuses `sortOrder`, no schema change); a reorder re-resolves Automatic defaults on the next read (no rescan, no network) and never touches per-episode pins. Durable invariants to keep: **files never move or get deleted** — "switch source" only changes which file the player opens (duplicates across drives are legitimate); resolution lives in the data layer (UI sees one `Episode`, never source-resolution types); watch state stays per logical episode (shared across sources).
